# Agent Note: 通过现有消息 surface 接纳同会话重发

Status: implemented

[English](2026-10-17-session-restart-admission.md) | 中文

## 问题

编辑较早输入或重新生成回答，必须让后续模型请求排除被替代的回答，同时保留原始记录。请求准备失败不能提前替换可见对话。

## 决策

[Session Controller](../../../../packages/api/session-controller/README.zh.md) 持有重发选择、持久意图与请求标识去重。现有队列持有待处理输入。循环在 pre-step 接收通用替换意图，仅在请求准备成功后通过已有 surface 替换操作提交。Chat 从意图与已接纳消息推导退场范围；草稿保持本地临时状态。

## 考虑过的替代方案

**修改或截断日志。** 这会销毁此前回答，并破坏仅追加持久化。

**每次编辑都创建分支会话。** 这保留了记录，却创建另一个会话，而不是从用户选择的会话内重新开始。

**在 Remote 处理器中替换历史。** 这会在路由解析仍可能失败时移除旧分支，并重复循环的接纳职责。

## 影响

事件日志仍是唯一持久历史。原始消息可查阅，只有已接纳分支进入模型。必需的重发事件让不认识它的读取器在执行前拒绝日志。工具与文件系统副作用不会回滚。已被压缩移除的输入不能编辑。去重确认已接纳工作，而非执行成功；明确取消的请求需要新标识才能再次运行。

## 验证

所属 Host 测试覆盖分支重建、重复接纳、最新轮次选择、提供方失败与准备失败。Chat 测试覆盖回放、实时更新、向前分页、取消草稿与最后轮次操作。完整浏览器场景通过隔离配置操作公开控件并刷新恢复。
